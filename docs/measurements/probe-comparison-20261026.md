# Scanner probe comparison — 2026-10-26

[Unedited sixteen-sample report](probe-comparison-20261026.json), generated by
[compare_scanners.mbtx](../../scripts/compare_scanners.mbtx). Both isolated
source trees were extracted from revision 511b057; the candidate replaced only
seed_scanner.mbt. Installed pinned third-party dependencies were identical.
The report fingerprints scanner source and both native executables.

The change computes the next rolling weak checksum and looks up its candidate
bucket once per byte. Budget admission and committed consumption share that
probe. The scanner still recomputes an unconsumed byte on retry, checks SHA-256
for every admitted candidate, records first matches and charges the same work.
Public APIs and serialized plans are unchanged. New tests replace a refused
suffix and exercise byte/budget boundaries for five window widths; existing
independent matching and two-window admission tests remain in the suite.

Environment: WSL2 Linux filesystem, CPUs 0 and 1, moon/moonrun 0.1.20261023,
moonc v0.10.17+d971670cd, native release. Both workers were built before timing.
Each file is 100 MiB + 17 bytes, with 1 MiB chunks and actual loopback HTTP,
zero injected delay. Each case ran ABBAABBA (A baseline, B candidate), four
fresh processes per condition. Local wall-clock observations include noise;
this is not an isolated benchmark lab or a statistical confidence interval.

All first eleven MFLSTRESS1 fields agreed within each case, across all eight
samples. Identical reused 104857617 bytes, transferred zero bodies and charged
106954888 candidate-hash input bytes. Low-reuse reused zero, made 101 artifact
requests carrying 104857617 bytes and charged 2097407 candidate-hash input
bytes. Workers independently checked whole output digest and input preservation.
The optimization did not trade fewer verification checks for lower timings.

Observed preview medians fell about 16.7% and 11.6% respectively. Update and
total medians also fell, but ranges overlap: the candidate identical update
sample of 16009 ms is retained. These observations justify the narrow internal
change; they do not establish universal performance superiority, faster
end-to-end delivery than full download, or results for other hardware, chunk
sizes, networks and targets. RSS samples are in the raw report; no memory
improvement is inferred. The earlier 1 GiB matrix has not been rerun with this
optimization and remains explicitly a baseline measurement.
